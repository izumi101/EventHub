# Internationalisation (kk / ru / en)

The UI is available in Kazakh (`kk`), Russian (`ru`) and English (`en`). The language switches at
runtime (no reload, one build for all languages). English is the source and the fallback.

## Why Transloco

`@jsverse/transloco` 8.4.0 (MIT, pinned exactly; peer `@angular/core >=16`, so it supports Angular 21).
Angular's built-in `$localize` produces one build per locale and cannot switch at runtime, which
the product requirement excludes. A hand-rolled service would have to re-implement lazy loading,
fallback, interpolation and testing utilities that Transloco already provides.
Everything project-specific (persistence, `<html lang>`, locale data, plurals) sits in
`frontend/src/app/i18n/`.

## How it works

| Piece | File |
|---|---|
| Active language, persistence, `<html lang>`, `t()`, `plural()` | `i18n/language.service.ts` |
| Provider (Transloco config, locale data, boot-time language load) | `i18n/i18n.providers.ts` |
| `ҚАЗ / РУС / ENG` switcher (topbar; also in the mobile drawer) | `i18n/language-switcher.component.ts` |
| `Accept-Language` on requests to our API | `i18n/accept-language.interceptor.ts` |
| Dates / numbers / plurals that follow the language | `i18n/locale.pipes.ts` (`localDate`, `localNumber`, `tPlural`) |
| Money (`money` pipe, Intl, ISO currency preserved) | `pipes/money.pipe.ts` |
| Route titles | `i18n/title.strategy.ts` (route `title` is a `routeTitles.*` key) |
| Test helper | `i18n/testing.ts` (`I18nTestingModule`, real en/ru/kk) |

Initial language: `localStorage["eventhub.lang"]` → `navigator.languages` → `en`.
All `localStorage` access is wrapped in try/catch.

Angular locale data for `ru` and `kk` is registered in `i18n/locales.ts`. The date, number and money
pipes are impure on purpose, so they re-render when the language signal changes. English keeps
12-hour times; `ru` and `kk` use 24-hour clocks (`h:mm a` becomes `HH:mm`).

## Files

`frontend/src/assets/i18n/{en,ru,kk}.json`, nested by feature: `nav`, `footer`, `home`, `event`,
`eventDetail`, `checkout`, `myRegistrations`, `myBookings`, `groupBooking`, `payment*`, `dashboard`,
`attendees`, … and `common` for shared words.

## Adding a string

1. Add the key to `en.json` and the same key to `ru.json` and `kk.json` (real translations, Cyrillic
   Kazakh with ә ғ қ ң ө ұ ү һ і). Keep product names (EventHub, Freedom Pay, QR) untranslated.
2. Template: `{{ 'feature.key' | transloco }}` or `{{ 'feature.key' | transloco: { name: value } }}`;
   attributes: `[attr.aria-label]="'feature.key' | transloco"`. Import `TranslocoPipe`.
3. Code (toasts, modals): `inject(LanguageService).t('feature.key', { name })`.
4. Plurals: define `key_one`, `key_few`, `key_many`, `key_other` (Russian needs all four, Kazakh and
   English `one`/`other`; `_other` is required). Use `{{ 'key' | tPlural: count }}`; `{{ count }}`
   is available in the string.
5. Dates and numbers: `localDate` / `localNumber`, never `date` / `number`. Money: `money`.
6. Run `npm test`. `i18n/translations.spec.ts` fails if a key exists in one file and not the others,
   if a string is empty, or if the `{{ params }}` differ between languages.

## Adding a language

1. Add the code to `SUPPORTED_LANGS` and `LANG_META` (`i18n/languages.ts`).
2. Register Angular locale data in `i18n/locales.ts` and add the Intl tag in `pipes/money.pipe.ts`.
3. Create `assets/i18n/<code>.json` with every key, import it in `i18n/testing.ts` and
   `i18n/translations.spec.ts`.

## Conventions

- Keys are camelCase, grouped by feature; reuse `common.*` before adding a duplicate word.
- Never concatenate translated fragments; use one key with `{{ params }}`.
- Do not translate data that comes from the API (event titles, category names, organizer notes).
- Backend error messages shown verbatim stay as the backend sends them (`apiErrorMessage` only
  translates its local fallback). The backend can localise later using `Accept-Language`.

## Known follow-ups

- `components/login/*`, `components/profile/*`, `services/auth.service.ts` and any 2FA files were
  being changed by another developer and are still English-only.
- `index.html` static `<title>` / meta tags stay English until `SeoService` takes over at boot.
- Static example placeholders (e.g. `your@email.com`) are intentionally identical in all languages.
- Currency labels such as `Price ($)` on the ticket-type form existed before this work and are
  untouched.
